# Таван Тансаг — вебсайтын эхний суурь

Монгол, Англи хэлтэй каталог, өв соёлын танин мэдэхүйн булан, зөвлөгөө хүсэх маягт болон Supabase-д холбох хүсэлт/CRM өгөгдлийн суурь. Эхний хувилбар нь **зурагт тулгуурласан 10 жишиг бүртгэлтэй туршилтын вебсайт** юм.

## Харах, ажиллуулах

Node.js 24 болон npm ашиглана.

```sh
npm ci
cp .env.example .env.local
npm run dev
```

Нээгдсэн Local хаягийн `/mn` эсвэл `/en` хуудсаар үзнэ. Supabase-ийн түлхүүргүйгээр каталог болон агуулгын хуудсууд ажиллана. Маягт холбогдоогүй үед илгээх товч идэвхгүй, Facebook холбоосыг харуулна.

```sh
npm run typecheck
npm test
npm run build
```

## Энэ хувилбарт бэлэн зүйл

- Бодит Drive зураг болон лого ашигласан нүүр хуудас.
- Хоёр хэлний каталог, ангиллын шүүлтүүр, нэр/кодоор хайлт.
- 10 эдлэлийн тус бүрийн дэлгэрэнгүй хуудас; сонгосон эдлэл маягтад дамжина.
- Өв соёлын булан, танилцуулга, мэдээллийн нууцлалын эхний агуулга.
- Гар утасны цэс, хэл солих, гарын товчлуураар удирдах боломж, хөдөлгөөн багасгах тохиргоог хүндэтгэх загвар.
- Хүсэлтийн сервер талын шалгалт, давтан илгээлтийн хамгаалалт, бодит хадгалалтын дараах амжилтын хариу.
- Supabase-ийн migration, 10 жишиг бүртгэлийг SQL болгох скрипт, хүсэлт/харилцагч/ажлын даалгавар/үйл явдал/мэдэгдлийн дарааллын хүснэгтүүд.
- Нийтийн каталог болон хувийн CRM мэдээллийг салгасан хандалтын дүрмүүд.
- GitHub Actions-д зориулсан typecheck, тест, build шалгалт.

## Бүртгэл ба зураг

| Файл | Зориулалт |
|---|---|
| `data/catalog.json` | Эхний 10 жишиг бүртгэл, Монгол/Англи нэр ба тайлбар |
| `data/asset-manifest.json` | Зургийн эх файл, Drive холбоос, ашигласан хувилбарын мэдээлэл |
| `docs/catalog-review.md` | Дэлгүүрээс баталгаажуулах мэдээлэл, сонголтын тайлбар |
| `public/images/catalog/` | Вебд ашигласан бодит зургийн хувилбарууд |
| `supabase/migrations/` | Өгөгдлийн сангийн бүтэц ба эрхийн дүрэм |
| `docs/backend.md` | Өгөгдлийн санг холбох, шалгах заавар ба хязгаарлалт |

TT-001–TT-010 нь **жишиг бүртгэлийн код**. Зургаар ялгаатай харагдаж байгаа нь тус бүрийг бодит агуулахын нэгж гэж баталгаажуулсан гэсэн үг биш. Нэг эдлэлийн өөр өнцгийг давхар бүртгэсэн эсэхийг эзэмшигч эцэслэн нягтална. Үнэ, материал, хэмжээ, жин, урлаач, он цаг нь тодорхойгүй учраас `null`; үлдэгдэл `unverified`; нийтлэлт `sample`; баталгаажуулалт `needs_review` байна.

Каталог хоёр горимтой: `CATALOG_SOURCE=file` нь локал JSON файлыг уншина; `CATALOG_SOURCE=supabase` нь хуудсыг нээх бүрд Supabase-ээс зөвхөн нийтэд үзүүлэх талбаруудыг уншина. Тусдаа туршилтын санд `CATALOG_INCLUDE_SAMPLES=true` болгож 10 жишиг бүртгэлийг үзүүлж болно. Энэ тохиргоог унтраахад зөвхөн баталгаажсан, нийтлэгдсэн, хоёр хэлний орчуулга нь нийтлэгдсэн эдлэл харагдана. Холболт тасарвал локал өгөгдлөөр далд орлуулахгүй; дахин оролдох тайлбар гарна. Ажилтны засварлах дэлгэц дараагийн шатанд нэмэгдэнэ.

## Маягтыг нээхээс өмнө

1. Тусдаа хөгжүүлэлтийн Supabase төсөлд migration болон seed-ийг туршина. Үндсэн хэрэглэгчийн мэдээллийг preview орчинд оруулахгүй.
2. `.env.local` болон Vercel-ийн тохирох орчинд URL, серверийн нууц түлхүүрийг оруулна. Нууц түлхүүрийг GitHub, браузер, чат эсвэл `NEXT_PUBLIC_*` нэртэй хувьсагчид байрлуулахгүй.
3. Эдлэлийн бодит мэдээлэл, зураг ашиглах эрх, хүсэлтийг хүлээн авах ажилтан, нууцлалын агуулгыг батална. Эдлэлтэй хүсэлт авахын өмнө тэр эдлэл Supabase-д `published` + `verified` болсон байна.
4. Хөгжүүлэлтийн орчинд бодит хадгалалт, давтан хүсэлт, эрхийн тусгаарлалт, бүтэлгүйтлийн нөхцөлүүдийг шалгана.
5. Дараа нь `INQUIRIES_ENABLED=true` болгоно. Энэ тохиргоо анхнаасаа `false`.

`NEXT_PUBLIC_SITE_URL` нь тухайн байршуулалтын хаяг байна. Тохируулаагүй үед Vercel-ийн `VERCEL_URL`-ийг ашиглана. `SITE_ORIGIN`-ийг тохируулбал мөн тухайн хаягийн origin (замгүй, төгсгөлд `/`-гүй) байна. Хөгжүүлэлт, Vercel preview болон production-д өөр өөр утга ашиглана.

## Дараагийн хөгжүүлэлт

- Ажилтны Supabase Auth нэвтрэлт, хоёр шатны баталгаажуулалт, CRM-ийн хамгаалагдсан дэлгэц ба эрх шалгасан засварлах үйлдлүүд.
- Баталгаажсан бүтээгдэхүүн болон орчуулгын удирдлага; загвар, хувилбар, бодит агуулахын нэгжийг ялгах бүртгэл.
- Хүсэлтийн эзэн томилох, даалгавар, үнэ саналын хувилбар, борлуулалтын баталгаажуулалт.
- Мэдэгдлийн дарааллыг боловсруулах ажил, хүргэлтийн алдаа/дахин оролдлогын хяналт. Одоогоор **и-мэйл илгээхгүй**.
- Хүсэлтийн олон нийтийн нээлтээс өмнөх ботын хамгаалалт, эх үүсвэрийн түвшний хурдны хязгаарлалт, хадгалалтын хугацаа, нөөцлөлт ба сэргээх туршилт.
- GitHub репозиторт эх код оруулах, Vercel preview/production-ийг тусгаарлан холбох, домэйн ба хяналт тохируулах.

Онлайн төлбөр, сагс, хүргэлтийн автомат тооцоо, ажилтны бүрэн CRM дэлгэц энэ суурь хувилбарт хийгдээгүй. Хүсэлт нь захиалга, төлбөр эсвэл барааны нөөцлөлт үүсгэхгүй.

## Нийтлэхийн өмнөх хязгаар

`SITE_INDEXABLE=false` тул хайлтын системд индексжүүлэхгүй байх заавартай. Энэ нь нууцлалын хамгаалалт биш; preview холбоосыг хамгаалах тохиргоог байршуулалтын орчинд хийнэ. Баталгаажсан бодит агуулга болон ажиллах урсгал бэлэн болсон үед л индексжилтийг нээнэ.

Supabase болон Vercel-ийн алсын төсөл үүсгээгүй, төлбөртэй үйлчилгээ идэвхжүүлээгүй, GitHub руу push хийгээгүй. Бодит хэрэглэгчийн мэдээлэл импортлоогүй.
